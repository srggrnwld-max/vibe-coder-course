# VPa04 — Как мыслить как инженер и использовать ИИ в помощь

## Задача

Я хотел понять, какие проекты уже есть на моём компьютере и какие из них связаны с GitHub.

Своими словами задача звучала так:

> Найти на компьютере все проекты и показать, какие из них уже связаны с GitHub.

## Три версии промпта

### 1. Плохой промпт

> Найди все мои проекты и скажи, что есть на GitHub.

Проблема: непонятно, где искать, что считать проектом, что именно проверять в Git и можно ли что-то изменять.

### 2. Средний промпт

> Проверь мои рабочие папки на компьютере. Найди проекты, определи, где уже есть Git, и покажи, какие из них связаны с GitHub. Ничего не изменяй. Результат дай таблицей.

Это уже задаёт цель и ограничение, но остаются неясными границы поиска, признаки проекта, проверка секретов и критерии связи с GitHub.

### 3. Отличный промпт

> Проведи аудит всех моих локальных проектов на Windows-компьютере в режиме только чтения.
>
> Ищи в первую очередь в рабочих каталогах пользователя: Desktop, Documents и папке zerocode. Не сканируй системные каталоги, AppData, node_modules, venv, .venv, кэши и содержимое .git.
>
> Проектом считай папку, где есть характерные признаки разработки: .git, package.json, requirements.txt, pyproject.toml, README.md, main.py, server.js, src/ и подобные файлы. Не считай вложенную папку отдельным проектом, если она явно является частью родительского проекта.
>
> Для каждого проекта проверь:
> - полный путь;
> - тип проекта;
> - наличие .git;
> - текущую ветку;
> - git status;
> - количество коммитов;
> - последний commit;
> - наличие remote;
> - связь именно с GitHub;
> - URL репозитория;
> - наличие .gitignore;
> - наличие потенциально опасных файлов вроде .env.
>
> Содержимое секретных файлов не открывай и не показывай.
>
> Отдельно покажи проекты без Git.
>
> В конце дай таблицу со статусами:
> - GITHUB — СВЯЗАН;
> - GIT ЛОКАЛЬНО;
> - БЕЗ GIT;
> - ТРЕБУЕТ ПРОВЕРКИ.
>
> Затем сделай краткую сводку: сколько всего найдено проектов, сколько связано с GitHub, сколько имеют только локальный Git, сколько без Git, и какие проекты стоит разобрать в первую очередь.
>
> Ничего не создавай, не удаляй, не коммить и не пушь.

## Результат

ИИ провёл аудит и нашёл 18 проектных папок. Он правильно определил учебный проект VPa02/VPa03 как связанный с GitHub, нашёл локальный Git у интенсива «Первая ИИ-услуга» и выделил проекты без Git.

При независимой проверке GitHub обнаружился недочёт: у аккаунта был ещё приватный репозиторий `codex-learning`, которого не было в локальном отчёте. После уточнения выяснилось, что локальная копия этого репозитория в проверенных рабочих каталогах не найдена.

## Что ИИ сделал хорошо

- соблюдал режим только чтения;
- не открывал содержимое .env и других возможных секретов;
- разделил проекты на связанные с GitHub, локальные Git-репозитории и папки без Git;
- помог увидеть реальную структуру проектов на компьютере.

## Что нужно было улучшить

Первый запрос был ориентирован в основном на локальный компьютер, поэтому результат не давал полной картины удалённых репозиториев GitHub.

В следующем запросе я бы сразу добавил отдельный шаг:

> Получи список репозиториев моего GitHub-аккаунта и сопоставь его со списком локальных проектов. Отдельно покажи удалённые репозитории, для которых локальная копия не найдена.

## Короткий отчёт

Я работал с задачей инвентаризации проектов на компьютере и проверки их связи с GitHub. Плохой промпт был слишком общим, а отличный задавал область поиска, признаки проекта, ограничения безопасности и формат результата. ИИ хорошо разобрал локальные проекты, но первоначально не показал приватный репозиторий `codex-learning`, который существовал только на GitHub. В следующий раз я сразу добавлю перекрёстную проверку локальных проектов и удалённых репозиториев, чтобы получить полную картину.
